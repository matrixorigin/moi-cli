## 纵向：Workflow、Catalog、Knowledge 做到什么深度

### Workflow：从手工运行到自然语言创建、修改和恢复

- 能创建、复制、配置和运行工作流，区分普通 execution、Volume 父 dispatch 和文件 execution，逐条读取终态、节点结果和实际产物。
- 已验证 SQL、Python、流程控制、多上游绑定、Cron、Volume 触发、暂停/恢复/取消、失败重试和版本归属；恢复时不会把父任务 ID 当成文件 execution。
- 文档、PDF、Word、PPT、Markdown、HTML、Excel、图片、XML、文本与图文嵌入均有实际解析结果；增强解析能处理跨页表和图片内容。
- 训练数据集、信息提取、多模态和 RAG 均完成自然语言候选创建、候选测试、接受、部署和正式运行。RAG 首次运行暴露全限定向量表解析为空后，又通过自然语言修改生成新候选，覆盖带库名和裸表名测试，并在同 App v2 正式运行成功。
- 尚未解决 WF39 的真正输出修订、取消后恢复异常、分支完整管理和独立 AI 后端条件；这些仍单独列在限制中。

### Catalog：从资源查找到文件、血缘和清理核对

- 能浏览工作区、Catalog、数据库、表、Volume、文件、模型和算子，执行库表卷管理、文件详情、算子管理与发布、订阅库和文件夹管理。
- 上传、导入、下载和 SQL 结果能沿真实 database/volume/file ID 相互印证，不按文件名或列表顺序猜对象。
- Workflow 输入文件、解析产物、Knowledge 来源和最终引用已能串起来。RAG 的规则文档与 CSV 均与实际上传 file ID 一致。
- 删除验收会区分成果列表、Catalog placement 和物理文件元数据；placement 归零不自动等同物理擦除。
- 外部数据库目录、统一模型/算子树、算子多版本时间线和 system 保留字行为仍有问题或缺条件。

### Knowledge：从建库、准备到多轮问答和正式引用

- 能创建和维护知识库，添加文件或表来源，核对 source/job、持久文档、分段、启用状态和 ETag，不以 accepted 或 ingest 开始代替准备完成。
- 七类语义条目均有真实运行结果；单库多轮、多库联合问答、来源替换、启停和有效期均有相应证据。
- 图片检索已覆盖文本搜图、图片搜图、6 张图联合向量化和 36 个相似度单元；图片结论还核对实际读图工具与 visual_hit。
- RAG 正式运行回答每车 8 箱、53 箱至少 7 辆，5 条引用能回到当前 model/source/file/chunk；分段 1 给出 8 箱，分段 2 给出 53 箱。
- 外部数据库、独立 SQL 计算资源、普通成员权限、图片/表格编辑、分段搜索与批量删除仍需条件或正式合同。

## 任务可靠性、迁移与合同能力

- 3 套任务模板共 17 步：Catalog→Workflow→Knowledge、Workflow 候选创建修改、Agent 双版本与成果生命周期。任务模板就是预先写好的步骤和验收清单，不自动执行。
- 恢复检查区分可继续、未知提交、验收不全、验收失败、依赖等待和已完成；未知提交只查原对象，不能换 invocation ID 重发。
- 35 个 CLI 合同缺口有机器清单和禁止替代路径；缺正式入口时不能猜字段。
- 15 个结构化文件参数、3 个原始字节输入、3 个输出参数已登记，4 类凭证文件明确拒绝进入证据目录。
- 默认使用 dev CLI；macOS `/var`、`/tmp` 可以保存证据，最终输入文件为链接时仍拒绝。
- 发布验证包含 38 个本地测试、138 个产品命令帮助检查和 25 个文件参数检查。
