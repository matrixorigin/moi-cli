# 能力边界合同

## 判定原则

Skill 的覆盖单位是可核验的业务闭环，不是命令数量、页面记录数量或接口数量。回答用户
“已经能做什么”时，只能报告有限闭环清单和当前等级；不能用“接口都有了”“命令都存在”
代替完成判断。

## 状态与静态支持分开

`capability-cards.json` 的 `observations` 是唯一场景状态源。`passed`、`failed`、`partial`、
`blocked`、`cli_missing`、`unverified` 均针对具体场景、条件、验证日期与 CLI 渠道；
不设整个能力的“已通过”标签。目录、菜单映射和覆盖矩阵由同一数据生成，不能分别修改状态。
`static_support` 的层级和形态只描述文档组织，不证明线上可用。历史正文保留作追溯。

## 执行前范围判断

先通过 `scripts/capability_status.py query CAPABILITY_ID` 发现已登记场景，再用
`--scenario`、`--channel`、`--condition KEY=VALUE` 核对本次目标。只给能力 ID、
没有场景/条件或没有匹配时，保持 `unverified` / `needs_scope_match=true`。
读取返回的条件、来源与限制后，再按相关 Recipe 和目标机器的 CLI help/schema 核对入口。判断的是业务结果及
模型通道、文件格式、身份、版本、并发和外部副作用等实际条件，不能只匹配菜单或命令名。

- **在已验证且通过的范围内**：沿对应 Recipe 执行；仍须发现当前对象、检查前置条件并核验本次结果。
- **已有失败证据**：先说明“此条件下已实测未通过”、具体失败步骤和影响；不能把“已经测试过”当成可用。
  有补测授权时可对原范围有界复核；未取得同目标的成功证据前保留失败判断。
- **能力域内但场景未验证或仅部分覆盖**：执行前提示“此场景超出当前已验证覆盖范围”，
  说明已覆盖的部分、未验证条件、可能影响和拟采用的有界验证方法；不能承诺可完成。
- **当前 CLI/Skill 没有支持合同或任务不属于 MOI 能力域**：提示“此任务超出当前 moi-cli + Skill 的能力范围”，
  指出缺少的入口/合同或合适的任务归属；不猜参数、不切低层接口。
- **能力已覆盖但缺输入、权限、登录或外部目标**：明确说缺什么，不把条件不足说成能力不支持。

提示示例：“此场景超出当前已验证覆盖范围：已验两个相同新请求键同时提交的只读恢复流程，
尚未验外发通知节点。需要单独核对通知去重和接收结果，不能承诺重复请求不会重复发送。”

操作者已明确授权补测、探索或扩展覆盖时，先告知具体边界后可在既有授权内继续有界测试，
无需为相同范围重复确认；发现新的影响、费用或缺少必要授权时停止相关动作。探索记录与已验证
方法分开，只有真实结果核验通过后才更新覆盖等级。复杂任务逐步判断：可完成独立的已覆盖步骤，
不能把局部成功当成整个目标完成。

当前已确认的 10 个整体合同缺口和 25 个部分合同缺口，按[CLI 正式合同缺口清单](cli-contract-gaps.md)
逐项判断。机器可读源是 `references/cli-contract-gaps.json`；执行前可用
`scripts/cli_contract.py gaps --scope full_cli_missing` 或 `partial_cli_gap` 查询。清单未提供正式
入口时，不用开放 object/JSON 猜字段，也不用相邻命令成功代替本功能。

## 不变量

- 不用界面按钮、菜单可见、列表出现、提交 accepted 或模型自述作为完成证据。
- 不为排除状态、未知状态或缺失 schema 自动猜参数。
- 不通过 raw HTTP、数据库、core-cli、复制凭证、低层 SDK 或切换身份绕过 Product API。
- ID 只有来自服务端返回、已记录的本地 artifact 清单或用户明确给出时才是真实 ID。
- 同名对象允许存在；名称、标题、列表顺序、UI 展示和路径都不是唯一标识。

## 报告模板

报告当前能力或编排过程时至少包含：

```text
对象: 真实 ID 或“尚未选择”
动作: 正在执行/请求的动作
状态: present/pending/ready/failed/unknown
证据: 命令返回 ID、详情、目标资源查询、结果文件或短预览
限制: 缺失输入、权限、认证、异步预算、外部渠道或 CLI partial
```

没有对象就先完成发现和确认；没有证据就不报告完成。
