# 复杂任务模板与恢复合同

> 版本说明：本报告完整保留 0.4.12 内容基线的验收结果；5.2.3 进行仓库化与命名统一，未把基线结果冒充本轮新增线上验收。

## 结论

本版把三类已经跑通的复杂任务固化为任务模板，并增加恢复前的只读防重检查。它们让任务更容易接续，但不会自动执行或授权任何线上动作。

## 三套任务模板

这里说的任务模板，就是事先写好的工作清单：步骤、先后顺序、成功标准和恢复位置都已经列明。它只负责安排和检查，不会自己跑线上任务。

| 任务模板 | 步骤 | 关键验收 |
| --- | ---: | --- |
| `catalog-workflow-knowledge` | 4 | 非空输入、Workflow 本次执行、Knowledge 持久文档、正式引用 |
| `workflow-candidate-lifecycle` | 6 | v1 创建部署运行、自然语言修改、同 App v2、两版执行归属 |
| `agent-version-artifacts` | 7 | v1/v2、默认切换与回滚、成果下载、任务取消、包导出 |

`task_blueprint.py init` 只写私有 `run.json`，保存任务模板版本、输入、步骤依赖、验收条件和清理提醒。`recover` 只读，不调用 moi-cli。

## 恢复判断

| 状态 | 允许动作 |
| --- | --- |
| `ready_for_single_execution` | 只继续返回的一步，一条明确授权命令 |
| `blocked_unknown_submission` | 只查原对象；没有原 ID 就保持未决 |
| `acceptance_incomplete` | 只补原回执的验收，不重提 |
| `acceptance_failed` | 保留失败，另建有明确授权的恢复步骤 |
| `waiting_dependencies` | 先完成上游验收 |
| `completed` | 不再执行；清理单独确认 |

本地演示 `demo-ready.json` 显示只有 `inspect-input` 可继续；把该步改为已提交未知后，`demo-blocked-unknown.json` 显示所有新主调用被禁止。另一个独立测试拒绝两个步骤共用同一个主调用 ID。

## 文件与 CLI 合同

- 15 个结构化 JSON/SQL 文件参数、3 个原始字节输入、3 个输出参数有明确分类。
- 4 类凭证文件明确拒绝，不复制进证据目录。
- 25 组参数与当前 dev CLI help 一致。
- 35 个合同缺口统一登记，不用开放 JSON、raw HTTP、core-cli、数据库或相邻成功场景替代。
- 默认程序为 `$HOME/.local/bin/moi-cli-dev`；macOS `/var`、`/tmp` 可保存证据，最终输入文件仍禁止链接。

## 验证与限制

38 个测试通过，其中新增 11 个针对本版行为。任务模板不能验证线上资源是否存在，恢复检查也不能证明远端未接受请求；真正业务结果仍必须由正式 CLI 回执和对象读回证明。
